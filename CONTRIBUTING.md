# How to contribute to Astrea

Users are welcome to contribute either through new feature development, general updates, or bug fixes. Larger refactors should first be discussed with project leads.

## Generality
* You can use the IDE of your choice
* You must create a feature branch before merge
* You have to be in the mindset of the software craftsmanship
* Features must be developed with runtime speed in mind
* You must apply OOP principles
* You must apply [DRY principles](https://en.wikipedia.org/wiki/Don%27t_repeat_yourself) as much as possible
* You must follow the formatting laid out in .clang-format and must otherwise maintain neat, legible code
* Each development must be tested at least at the level of unit tests
* All tests and examples must run after new developments
* Code coverage of new features should never be below 90%.
 
## Documentation
* All new classes, functions, and header files must be documented.
* Documentation goes in header files and follows standard doxygen formatting

## AI Usage
* You can use AI tools to help you write code, but you must review and understand all code generated by AI tools before including it in the project.
* You can also use AI tools to help with small snippets, boilerplate code, or to help write function documentation. In these cases, you must still review and understand the generated code and documentation before including it in the project.
* You must not use AI tools to generate large portions of code. This includes entire classes, functions, or modules.
* You must not use AI tools to generate code that you do not understand or cannot explain. If you cannot explain how a piece of code works, you should not include it in the project, even if it was generated by an AI tool and proven to work under proper testing.
* Any PRs that include AI-generated code must include a comment indicating which parts of the code were generated by AI tools and what tools were used. This is for transparency and accountability in the development process.
* Any violations of these rules, subject to the opinions of the reviewers and project leads, will result in the offending code being removed from the project and the contributor being asked to rewrite the code without AI assistance. Repeat violations may result in a ban on contributions from the offending contributor.
